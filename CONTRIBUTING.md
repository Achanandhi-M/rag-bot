# Contributing to Keploy RAG Chatbot

Thank you for your interest in contributing to the **Keploy Rag Chatbot**! 🙌 Keploy is a project by developers, for developers, and there are many ways you can contribute. Whether you're fixing bugs, suggesting new features, or improving documentation, your contributions are highly valued.

If you're not sure where to start, ask us in our [Slack channel](https://join.slack.com/t/keploy/shared_invite/zt-357qqm9b5-PbZRVu3Yt2rJIa6ofrwWNg).

## Prerequisites for Contributors

Before contributing, please ensure you have the following:

- Basic knowledge of **Git** for version control.
- Understanding of **Python**, **Go**, and **Markdown**. These skills are essential as the project utilizes these technologies extensively.
- Familiarity with **MongoDB**, **Azure OpenAI**, and **LangChain** would be helpful.

We recommend setting up the Keploy project locally, exploring the code, running the tests, and familiarizing yourself with the architecture. This will make your contribution process smoother.

## Contribution Guidelines

We welcome contributions from everyone! Follow the general contribution flow and the specific Keploy flow as outlined below.

### General Contribution Flow

1. **Fork the repository**: Create a personal copy of the repository by clicking on the “Fork” button at the top right of the project page.
   
2. **Clone your fork**: Clone the forked repository to your local machine.

    ```bash
    git clone https://github.com/<your-username>/keploy-chat-api.git
    cd keploy-chat-api
    ```

3. **Create a feature branch**: Always create a new branch from `main` to work on your feature or fix.

    ```bash
    git checkout -b feature/your-feature-name
    ```

4. **Make your changes**: Implement the feature, fix the bug, or improve the documentation. Be sure to keep your changes focused and well-tested.

5. **Commit your changes**: Write clear and concise commit messages explaining what you’ve done.

    ```bash
    git commit -m "Add feature X or fix bug Y"
    ```

6. **Push to your fork**: Push the changes back to your forked repository.

    ```bash
    git push origin feature/your-feature-name
    ```

7. **Create a pull request (PR)**: Go to your GitHub repository and create a pull request from your feature branch to the main repository.

8. **Sign-off on Commits (Developer Certificate of Origin)**: For every commit you make, you must sign off using the Developer Certificate of Origin (DCO). This indicates that you have the legal right to submit the code.

   Add the sign-off to each commit by using `-s` when committing:

   ```bash
   git commit -s -m "Your commit message"
   ````

   This adds a line to your commit message:

    ```bash
   Signed-off-by: Your Name <youremail@example.com>
   ```

   If you forget to sign off, you can amend your commit to add the sign-off:
    ```bash
    git commit --amend --signoff
    ```

## Opening Issues

Before submitting a pull request, **please check if the issue is already reported**. If not, feel free to open a new issue to discuss the bug or feature you want to address. Here's what to include in your issue:

* A clear description of the problem or feature request.
* Steps to reproduce the bug (if applicable).
* Any relevant error messages, logs, or screenshots.

---

## Feature Requests

If you would like to request a new feature, please create an issue and provide detailed information, including:

* **Why** the feature is useful.
* **How** it should function.
* Any **use cases** or **examples** that can help explain the feature.
